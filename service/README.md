# service — продуктовый слой

Русский веб-прототип поверх `cardiag`: запись звука из браузера, согласование
голов модели, честная подача результата и сбор корпуса для дообучения.

Каталог намеренно отделён от `src/cardiag`. Апстрим подтягивается без
конфликтов, потому что ни один файл модели здесь не правится.

## Запуск

```
uvicorn service.app:app --host 0.0.0.0 --port 8080
```

Модели грузятся один раз при старте. Загрузка CLAP занимает около 9 секунд,
сам анализ — 0.23 секунды на CPU (замер: Windows 10, Python 3.11.16, 4 ядра).
GPU не нужен. Полный цикл HTTP-запроса с конвертацией ffmpeg — около 500 мс.

Нужен `ffmpeg` в PATH: браузер отдаёт webm/opus, а модель ждёт WAV 48 кГц моно.

## Почему сырой вывод модели не показывается

**Головы не согласованы между собой.** `region` и `cause` обучались раздельно,
поэтому выдают несовместимые пары. На `demo.wav` из репозитория это
одновременно зона «подвеска/рулевое» и деталь «выхлоп». `labels_ru.zones_agree`
проверяет совместимость, и при расхождении сервис называет только зону.

**Головы `cause` и `region` не откалиброваны.** В `best_model_clap.joblib`
температуры равны `{'cause': 1.0, 'region': 1.0}` — шкалирование к ним не
применялось вообще. Их «0.98» это сырой softmax, а не вероятность.
Откалиброваны только `kind` (3.081), `knock` (1.726) и отдельная модель триажа.
Поэтому заголовок строится на триаже, а проценты по узлам наружу не уходят
совсем: они лежат в `debug` для разработчика.

## Что известно про точность

Вокабуляр снят с самой модели, а не из документации: там **21** класс `cause`
и 6 классов `region`, тогда как `MODEL_CARD.md` говорит про 12. Среди меток
есть `bad_wheal_bearing` и `wheel_bearing` — один узел, размазанный по двум
меткам из-за опечатки в обучающем корпусе. Обе ведут на одну русскую карточку.

Проверено на одной машине с подтверждённым диагнозом: на записи холостого хода
модель дала зону `engine` и деталь `valvetrain`, автосервис независимо
подтвердил проблему с клапанами. Вывод держится на каждом 8-секундном окне
записи и воспроизводится побайтово, то есть это устойчивый сигнал, а не
случайность. Одного случая мало для оценки точности — для этого и собирается
корпус.

## Известные ограничения

Модель не умеет отвечать «это не автомобиль». На синтетическом тоне 220 Гц она
выдаёт «fault, ходовая часть, средняя уверенность». Нужен отдельный guard на
чужеродный звук, иначе пользователь с мусорной записью получит уверенный
неверный ответ.

Записи в движении непригодны: шум дороги перебивает дефект, и модель честно
скатывается в `uncertain`. Мастер записи ведёт пользователя к записи на
стоянке, но запретить он не может.

## Сбор корпуса

```
corpus/
  audio/<id>.wav
  records.jsonl     одна строка на анализ
  feedback.jsonl    что реально нашли в сервисе
```

`consent_training` хранится вместе с записью: без явного согласия аудио нельзя
использовать для дообучения (152-ФЗ). `GET /api/stats` показывает, сколько
собрано, сколько подтверждено и сколько раз вердикт совпал с реальностью — это
единственная честная метрика качества в проде.

## Перед продом

- Хостинг в РФ, персональные данные не должны уезжать за границу.
- Выкачать CLAP в образ или в своё S3: при каждом деплое тянуть 2 ГБ с
  HuggingFace нельзя.
- Ограничение частоты запросов и размера загрузки (сейчас только 25 МБ).
- `corpus/` переехать на S3, `records.jsonl` — в PostgreSQL.
